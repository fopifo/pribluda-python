# AGENTS.md — правила для ИИ-соавторов проекта "Приблуда на python"

Этот файл — инструкция для любого ИИ, работающего над проектом.
Попадает в каждый дамп (tools/make_dump.py). Читается ПЕРВЫМ.

## Роль
Ты — второй разработчик. Владелец — трейдер-скальпер без опыта
программирования: он копирует и вставляет код как есть, не редактируя
руками. Код должен быть рабочим СРАЗУ, без "доработай сам",
без пропущенных импортов.

## Золотое правило взаимодействия (читать при каждой сессии)
Владелец не выполняет ручные шаги. Любое изменение, требующее
создания папки/файла/модификации — оформлять как:
- команды в консоль (PowerShell/cmd), которые можно скопировать 1-в-1;
- код файла целиком;
- либо явно спросить «пришли текущий файл» вместо переписывания вслепую.

Никаких «создай папку», «положи туда», «не забудь» без точной команды.
Проверять каждый шаг перед отправкой: что реально на диске у владельца
(по присланному файлу), а что я выдумал.

Если мне нужны какие-то строки из файлов — я пишу команды для терминала
для владельца, а владелец присылает хвосты вывода.

## Жёсткие правила
- Работать только в ветке `Qwen_coder`, не пушить в `main`.
  Перенос в main решает владелец вручную после проверки.
- Секреты — только через .env/os.environ; .env не коммитить.
- Не совершать сделки и не выставлять ордера — только чтение данных.
- Не удалять существующий функционал без явной команды владельца.
- После содержательного изменения — commit (на русском) и push в Qwen_coder.
- В начале сессии проверить `git remote -v` и `git branch --show-current`.

## Baseline A/B (замер 2026-08-22, до дальнейшей докрутки)
- Эталон: 142 записи (63 за 20.08 + ~79 за 21.08 из supplement).
- TP=0, FN=142, FP=1270.
- **TP=0 — не провал детектора, а следствие tick-rule** (см. ниже).
  На сырой ленте конкурента (sngsp.csv) детектор корректно видит
  робота `buy qty=[64,65] повт=25 int=15.0s`, но на QUIK-ленте
  (quik_trades.csv) той же серии нет — стороны tick-rule рвут серию.
- Дальнейшая докрутка детектора до уровня конкурента возможна только
  через источник с истинными сторонами (QUIK API с `operation`, или
  другая лента). Пока используем QUIK+tick-rule и знаем об ограничении.

## Корень TP=0: tick-rule в QUIK (важный finding 2026-08-22)
- В этом QUIK **бит направления во flags обезличенных сделок не
  взводится, operation отсутствует** → сторона определяется ТОЛЬКО
  через tick-rule (export_trades v3.10).
- Tick-rule эвристика по изменению цены часто ошибается в боковике:
  одна и та же серия робота на QUIK-ленте видна как рваная
  (buy→sell→buy) и не проходит фильтр детектора.
- **Доказательство:** research/replay_sngsp.py по сырой ленте
  конкурента (data/sngsp.csv с настоящими сторонами) видит робота
  `buy qty=[64,65] повт=25 int=15.0s` (ровно то, что показывает
  конкурент). По quik_trades.csv того же тикера SNGSP — не видит.
- Это означает: детектор работает правильно, проблема в источнике
  данных. Задача следующего цикла — найти источник истинных сторон.

## Ревью и фиксы 2026-08-22
- **Баг №1 (eval в load_ref).** В research/ab_compare.py функция
  load_ref() парсила эталон через `eval(line, {"__builtins__": {}}, {})`.
  JSON `null` (когда время не распознано) для eval в урезанном
  окружении — NameError; `except Exception: continue` глотал — запись
  исчезала без предупреждения. Фикс: `json.loads(line)`. Эталон вырос
  с 63 до 142 записей — доказательство, что баг был реальным.
- **Баг №2 (голый datetime.now()).** В двух местах время бралось без
  явной зоны (полагалось на системные часы = МСК):
  - detectors/interval_robot.py, `_write_history` — пишет в
    robots_history.jsonl (сравнивается с эталоном, тот всегда в МСК);
  - gui/main_window.py — часы вверху окна и `now_ts` в `_refresh()`.
  Фикс: `datetime.now(MSK)` (MSK = ZoneInfo("Europe/Moscow")).
  Безопасная правка, поведение не меняет, убирает скрытое допущение.

## Правила PowerShell (важно для работы с владельцем)
- Длинные here-string (`@"..."@`) в PSReadLine падают с ошибкой
  `System.ArgumentOutOfRangeException: Значение должно быть больше
  или равно нулю и меньше, чем размер буфера` — это баг PSReadLine,
  не пользователя. Обход:
  - файлы писать через `python -c "..."` одной командой;
  - либо разбивать длинный here-string на несколько коротких pipe-команд;
  - либо `@"..."@ | Set-Content -Path file -Encoding UTF8`, но
    строго следить, что `"@` стоит **в самом начале своей строки**
    (без пробелов перед, без текста после).
- При склейке here-string и следующей команды в одну строку PowerShell
  может решить, что строка не закрыта, и выдать "Непредвиденная
  лексема". Правило: каждая команда — отдельным вставлением, дождаться
  возврата промпта `PS ...>` перед следующей.

## Проверенные особенности Quik/ISS (зонды probe_params.lua, 2026-08-20..21)
- getParamEx отдаёт значения одиночными вызовами, но НЕ выдерживает
  массовый опрос (506 тикеров за цикл) — поэтому планки собираются
  ломтиками 2/2 c (полный обход ~8 мин).
- В этом Quik getParamEx отдаёт param_type СТРОКОЙ ("1") — сравнивать
  только через tonumber (иначе всегда nil; это причина старых
  "Limits written: 0").
- Бит направления во flags обезличенных сделок не взводится, operation
  отсутствует → сторона ТОЛЬКО tick-rule (export_trades v3.10).
- ISS отдаёт котировки акций, но НЕ отдаёт PRICEMAX/PRICEMIN по
  акциям — планки только из Quik.
- В Quik CLOSE не отдаётся до первой сделки дня — используется
  PREVWAPRICE; TRADINGSTATUS приходит с param_type=4 (get_num
  принимает 1 и 4).
- Коды TRADINGSTATUS у ISS другие — в quik_quotes.csv не пишутся;
  статусы аукционов вкладка "Аукционы" берёт по расписанию MOEX.
- Класс SPBFUT в терминале не подключён — фьючерсов в котировках нет
  (не критично: фандинг берётся с ISS fort).
- Таблица "Текущие торги" должна быть открыта со всеми TQBR и
  параметрами, иначе getParamEx пустой (поток параметров не принимается).
- Пути к data/ из gui/tabs/<вкладка>/ — 4 уровня .parent до корня
  (баги stats_tab и limits_tab исправлены; в новых вкладках проверять
  сразу).
