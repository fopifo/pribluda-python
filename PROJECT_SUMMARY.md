# Приблуда на python — контекст проекта

Скринер торговых роботов (алгоритмов) на Московской бирже (MOEX).
Заказчик — трейдер-скальпер без опыта программирования, торгует на
MOEX через API Алор. Цель: одним из первых находить работающие
алгоритмы в ленте сделок и заходить в сделку вслед за ними. Также
следит за арбитражными связками (обычка/префа) и держит под рукой
фандинг/новости.

## Архитектура (кто за что отвечает)

- `detectors/interval_robot.py` — ядро детекции. `IntervalRobotDetector`
  ведёт активных "кандидатов" (Candidate) по каждой стороне (buy/sell)
  тикера, продлевает серию, если новая сделка укладывается по объёму и
  интервалу. Два режима матчинга объёма/интервала — strict (точный
  объём + допуск по интервалу) и TWAP (`ignore_qty=True`, объём не
  важен, интервал строже). Каждая серия при закрытии считает джиттер
  (стандартное отклонение интервалов, мс) — чем ниже, тем увереннее,
  что это автомат, а не совпадение/имитация.
- `arbitrage/pair_monitor.py` — `PairMonitor` следит за парой
  инструментов. Два режима: `ratio_pct` (отношение цен, % отклонения)
  и `absolute_rub` (абсолютная разница цен в рублях — для пар вроде
  MTLR/MTLRP, где "прострел" спреда — ХОРОШИЙ сигнал, возможность, не
  тревога). Гистерезис (RESET_FACTOR) защищает от повторного
  срабатывания на шумных колебаниях у самой границы порога. Отдельный
  сигнал "схождение" — когда пора закрывать позицию.
- `live_screener.py` — точка входа бэкенда. WebSocket к Алору
  (AllTradesGetAndSubscribe), кормит и детекторы роботов, и мониторы
  арбитража тем же потоком сделок. Настройки тикеров применяются на
  лету (settings_watcher_loop перечитывает ticker_settings.json). Лог
  событий — `output/live_signals_<дата>.txt`, ротация 14 дней.
- `gui/window.py` — главное окно (Tkinter), 4 вкладки (Роботы /
  Арбитраж / Фандинг / Новости). `gui/mini_window.py` — компактный
  оверлей поверх торгового терминала.
- `tg_bot/` — `bot.py` (push-уведомления, только арбитраж режима
  ratio_pct пока — absolute_rub ещё не подключён к Telegram),
  `menu_bot.py` (интерактивное меню: Арбитраж/Фандинг/Новости, отдельный
  процесс/поток, слушает входящие через getUpdates), `funding.py` /
  `news_moex.py` (независимые кэши данных с MOEX ISS).
- `start_all.py` — единая точка входа: GUI (главный поток, требование
  Tkinter) + бэкенд-скринер (фоновый поток) + Telegram-меню (ещё один
  фоновый поток).

## Известные ограничения и решения

- **Telegram иногда недоступен** из текущей сети (домен и IP) — код
  устойчив к этому (переподключение, не роняет остальное), но
  push-уведомления в такие моменты не доходят.
- **Роботы не идут в Telegram** — осознанное решение, сигнал приходит
  с задержкой (только на закрытии серии), для скальпинга бесполезно.
- **`absolute_rub` арбитраж не в Telegram** — временно, пока
  `tg_bot/bot.py` не обновлён под оба режима (только формат для
  `ratio_pct`/проценты сейчас).
- **T-Invest API (Т-Банк)** — подключение отлажено (обход
  PyPI-карантина, protobuf/Python 3.14 конфликт решён), но метода
  получения новостей в клиенте не оказалось — эта ветка не пригодилась,
  используем только MOEX для новостей.
- **CScalp / Alor Astras** — нет открытого API для программного
  доступа, не интегрированы.

## Найденные закономерности (из анализа логов)

- **TWAP-паттерн подтверждён на практике**, не только в теории —
  несколько тикеров (PLZL, BELU и другие) показывают десятки сигналов
  с одинаковым таймингом, но разным объёмом за один день — привело к
  добавлению пресета `twap_strict`.
- min_qty у большинства тикеров задан вручную в ticker_settings.json
  (не через процентиль) — подобран трейдером по опыту наблюдения.

## Рабочий процесс с DeepSeek (второй ИИ-помощник)

Делегируются: вспомогательные скрипты анализа логов (не боевую логику
детектора/арбитража), написание тестов (на проверку сюда), разбор
больших объёмов исторических данных. Важно: DeepSeek не может
переварить сырые логи целиком (ограничение по объёму) — поэтому
`analysis/weekly_review.py` делает тяжёлую агрегацию заранее и отдаёт
компактный отчёт, а не сырые данные.

## Инструменты для анализа истории

- `analysis/run_detectors.py` + `analysis/save_trades.py` — "перемотка"
  детекторов по сохранённой исторической ленте сделок (не обновлялись
  долго, актуализированы одновременно с реорганизацией папок).
- `analysis/analyze_parallel.py` — находит кластеры параллельных
  сигналов (TWAP-кандидаты) в одном логе.
- `analysis/weekly_review.py` — сжатый отчёт по нескольким дням сразу:
  устойчивость джиттера и TWAP-паттерна день от дня по каждому тикеру.
